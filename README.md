# Loop — маршрут по интересным местам

Пешее приложение на Flask и Leaflet: пользователь ставит на карте точки **A** и **B**, выбирает категории мест, максимальный «крюк» и количество остановок — приложение подбирает остановки по пути, строит пеший маршрут по улицам и ведёт по нему с GPS-подсказками. К остановкам подтягиваются фотографии и краткие описания из Wikimedia Commons / Wikipedia.

## Локальный хостинг на своём устройстве

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
./start.sh
```

`start.sh` запускает приложение через **Gunicorn** на `0.0.0.0:5050` и печатает адреса:

- `https://127.0.0.1:5050/` — на этом компьютере;
- `https://<IP-компьютера>:5050/` — с телефона в той же Wi-Fi сети.

Для GPS на телефоне нужен HTTPS-контекст, поэтому при первом запуске автоматически создаётся самоподписанный сертификат в `certs/` (папка в `.gitignore`). Браузер покажет предупреждение — это нормально: нажмите «Дополнительно» → «Перейти на сайт», после чего разрешите геолокацию. Сертификат действует для текущего LAN-IP; если IP изменился, удалите `certs/` и перезапустите.

Если GPS не нужен и хочется обычный HTTP:

```bash
HTTPS=0 ./start.sh
```

Тогда приложение откроется по `http://127.0.0.1:5050/`, но на телефоне геолокация работать не будет.

На macOS можно дважды кликнуть `start.command` — откроется Терминал и хостинг запустится.

Чтобы оставить сервер работать после закрытия терминала:

```bash
nohup ./start.sh > loop.log 2>&1 &
```

Настройки лежат в `.env` (файл не попадает в git):

```dotenv
HOST=0.0.0.0
PORT=5050
HTTPS=1
```

> Порт 5000 на macOS часто занимает AirPlay Receiver, поэтому используется 5050. Если порт занят, задайте другой: `PORT=5051 ./start.sh`.

> Приложение не имеет аутентификации. Открывайте его только в доверенной домашней сети. При первом запуске macOS может спросить разрешение на входящие соединения — разрешите для Python.

Для разработки с автоперезагрузкой Flask:

```bash
FLASK_DEBUG=1 python app.py
```

## Карта

- Подложка — **всегда стандартные тайлы OpenStreetMap** (`tile.openstreetmap.org`), без API-ключей и сторонних стилей.
- В тёмной теме те же OSM-тайлы приглушаются CSS-фильтром; источник карты не меняется.
- Если тайлы не загрузились, приложение показывает понятное уведомление.
- Параметры «Отступ области», «Максимальный крюк» и «Максимум остановок» можно менять ползунком **и вводить числом с клавиатуры**. Значения синхронизированы; работают стрелки `↑/↓` и `Enter`, на телефоне открывается цифровая клавиатура.

## Два режима старта

В карточке точек есть переключатель:

- **«От меня»** — при заходе приложение автоматически запрашивает GPS, ставит точку A на текущее местоположение и центрирует карту. Остаётся только кликнуть по карте и выбрать точку B. Нажатие на строку «Моё местоположение» обновляет GPS.
- **«От точки A»** — ручной режим: первый клик по карте ставит A, второй — B.

Выбранный режим сохраняется в `localStorage`. Если доступ к GPS запрещён, приложение показывает причину и остаётся возможность переключиться на ручной режим или повторить определение, нажав на строку A. На телефоне автоопределение требует HTTPS — используйте адрес из `start.sh`.

## Фото и описания достопримечательностей

Данные загружаются лениво и не блокируют карту:

1. Ищется статья **Википедии** рядом с координатами объекта — из неё берутся краткое описание и, если есть, фото.
2. Если фото нет, ищутся снимки рядом с координатами в **Wikimedia Commons**.
3. Последний резерв — поиск по названию в Wikimedia Commons.

Для защиты от тёзок («Парк Победы» в другом городе) статья Википедии проверяется по координатам: если она находится дальше 50 км от объекта, она отбрасывается.

Особенности:

- в карточке остановки показываются фото и первые 2 строки описания;
- в попапе — полное описание, фото, автор/лицензия и ссылка на источник;
- сервер кэширует результаты на 24 часа (отрицательные — на 5 минут);
- запросы к Wikimedia выполняются последовательно с мягким лимитом, чтобы не получать 429 Too Many Requests;
- браузер кэширует данные в рамках сессии;
- для маршрута подгружаются данные первых 8 остановок (по 3 параллельных запроса);
- клик по месту на карте догружает фото и описание при открытии попапа;
- если описания нет, показывается только фото; если нет и фото — цветная заглушка с номером остановки.

Фото отдаются с `upload.wikimedia.org` / `thumb.wikimedia.org`, ссылки ведут на страницы Wikimedia. При публичном использовании проверяйте требования конкретной лицензии.

## Навигация по GPS

После построения маршрута появляется кнопка **«Начать навигацию»** в карточке маршрута и кнопка-стрелка на карте.

Что делает режим навигации:

- следит за GPS через `navigator.geolocation.watchPosition` с высокой точностью;
- показывает синюю точку с направлением и круг точности;
- автоматически держит пользователя в центре карты (если сдвинуть карту вручную — появится кнопка возврата к слежению);
- подсвечивает пройденную часть маршрута;
- показывает следующий манёвр крупной стрелкой и текстом: «Поверните налево», «Держитесь правее», «В конце дороги поверните направо» и т.п.;
- показывает расстояние до манёвра, оставшееся расстояние, время и расчётное время прибытия;
- озвучивает подсказки по-русски через Web Speech API (голос можно выключить);
- предупреждает, если вы отклонились от линии маршрута;
- сообщает «Вы на месте» по прибытии;
- по возможности удерживает экран включённым через Wake Lock.

Ограничения:

- на телефоне GPS работает только по HTTPS — используйте адрес из `start.sh`;
- если браузер всё равно считает самоподписанный сертификат небезопасным, используйте `mkcert` или туннель `cloudflared`/`ngrok` с доверенным HTTPS;
- автоматической перестройки маршрута при уходе в сторону пока нет — приложение подсказывает вернуться на линию;
- точность зависит от GPS телефона; в помещении возможны погрешности;
- голосовые подсказки зависят от поддержки Web Speech API браузером.

## Источники данных и фолбэк

1. Сначала запрашивается **Overpass API** (официальное API и публичные зеркала).
2. Если все зеркала недоступны, ответ идёт из локального `saratov.geojson`.
3. Источники **не смешиваются**: когда Overpass снова заработает, локальные места просто перестанут использоваться.
4. Кнопка **«Повторить запрос»** принудительно проверяет Overpass, даже если сработал предохранитель.
5. Неудачные зеркала временно (по умолчанию 90 секунд) исключаются из опроса.
6. Результаты поиска кэшируются: живые — на 2 минуты, локальные — на 30 секунд.

Локальный набор содержит только Саратов, поэтому при выключенном Overpass и точках за пределами Саратова приложение честно сообщает, что мест нет.

Из `saratov.geojson` удалены клубы (ночные, подростковые, спортивные и т.п.) — 75 объектов. Те же правила фильтрации применяются к живому Overpass, поэтому клубы не возвращаются при работающем API.

## Настройки через переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `HOST` | `127.0.0.1` | Адрес сервера (`0.0.0.0` — доступ по сети) |
| `PORT` | `5000` | Порт; в `.env` проекта указан `5050` |
| `HTTPS` | `1` | `1` — HTTPS с автосертификатом, `0` — только HTTP |
| `FLASK_DEBUG` | выключен | `1`/`true` включает отладочный режим |
| `OVERPASS_TIMEOUT` | `8` | Таймаут запроса к Overpass, сек |
| `OVERPASS_COOLDOWN` | `90` | Пауза перед повторной проверкой упавшего зеркала, сек |
| `ROUTING_TIMEOUT` | `12` | Таймаут запроса к маршрутизатору, сек |
| `MAX_BBOX_DIAGONAL_KM` | `150` | Максимальный размер области поиска |
| `WIKIMEDIA_TIMEOUT` | `6` | Таймаут запроса к Wikimedia, сек |
| `WIKIMEDIA_MIN_INTERVAL` | `1.0` | Минимальная пауза между запросами к Wikimedia, сек |

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/points` | Совместимость: последнее состояние на сервере |
| `POST` | `/api/points` | Явно сохранить `point_a`/`point_b` или поставить точку по `lat`/`lon` |
| `POST` | `/api/search-places` | Найти места в bbox точек A и B |
| `POST` | `/api/build-route` | Подобрать остановки и построить пеший маршрут |
| `GET` | `/api/place-image?name=&lat=&lon=` | Найти фото места в Wikimedia |
| `GET` | `/api/place-info?name=&lat=&lon=` | Фото и краткое описание места |

Новый фронтенд передаёт `point_a` и `point_b` в каждом запросе поиска/маршрута, поэтому два пользователя не перетирают точки друг друга. Серверный `/api/points` оставлен для обратной совместимости.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют валидацию координат, защиту от слишком большой области, локальный фолбэк, отсутствие смешивания источников, фильтрацию клубов, сборку маршрута, разбор шагов OSRM для навигации, эндпоинты фото и описаний.

## Безопасность и устойчивость

- Строгая CSP: скрипты и стили только с этого домена; Leaflet лежит локально в `static/leaflet`.
- Самоподписанный TLS-ключ и `certs/` не попадают в git; папка в `.gitignore`.
- Изображения разрешены только с `upload.wikimedia.org` и `thumb.wikimedia.org`; URL проверяются на HTTPS и допустимый хост.
- Ограничение размера запроса (1 МБ) и валидация всех чисел (включая `NaN`/`Infinity`).
- Ограничение диагонали области поиска — защита Overpass и сервера от гигантских запросов.
- Проверка `Origin`/`Sec-Fetch-Site` для изменяющих POST-запросов.
- Все названия и подписи экранируются на клиенте — данные OSM и Wikimedia не могут внедрить HTML/JS.
- Таймауты и предохранители для Overpass, OSRM и Wikimedia; длинный маршрут режется на куски по лимиту OSRM.
- Таймауты `fetch` на клиенте, отмена устаревших запросов, блокировка повторных нажатий.

Ограничения: приложение не содержит аутентификации и rate limiting. Для публикации в интернете нужен reverse proxy, HTTPS и лимиты запросов; для домашней сети достаточно `./start.sh`.

```
tests/test_app.py          тесты
```
